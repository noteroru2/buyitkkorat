## แหล่งภาพและข้อจำกัด

ใช้ไฟล์ที่มีอยู่ใน `src/assets/images/realistic/` จำนวน 10 รูป: ภาพหลัก 9 หมวด และภาพ LINE CTA ร่วมอีก 1 รูป ไม่ได้ดาวน์โหลดหรือสร้างภาพใหม่ หน้าหลายรุ่นใช้ภาพตัวแทนหมวดเดียวกัน จึงไม่ใช่ภาพเฉพาะรุ่นของทุกหน้า

เอกสาร `docs/UXUI-V3-REALISTIC-IMAGES-INTEGRATION.md` ระบุว่าชุดนี้เป็นภาพประกอบเสมือนจริงที่สร้างไว้ **ไม่ใช่ภาพถ่ายสินค้าจริงหรือภาพถ่ายร้านที่ยืนยันแหล่งที่มาแล้ว** ไม่พบชุดภาพถ่ายจริงสำหรับใช้แทนทุกหมวดใน assets ของเว็บไซต์ ภาพ AI เก่าที่ใช้ประกอบขั้นตอนบริการ 2 รูปยังคงแยกจากภาพหลักและมีคำอธิบายเดิม

หากต้องการภาพถ่ายจริงแทนภาพเสมือนจริงทั้งหมด ยังต้องจัดหาภาพถ่ายเพิ่มเติม การเปลี่ยนครั้งนี้แก้การแสดงภาพวาด SVG ในตัวอย่างให้ใช้ไฟล์ภาพที่มีใน repo

## การแก้ไข

- เชื่อม `coverVisual` เข้ากับ Hero ของหน้าบริการ และภาพหลักของหน้าแรก
- เพิ่มภาพใน layouts ของพื้นที่และข้อมูลร้าน รวมถึงหน้ารวมและ 404
- ปรับการเลือกภาพของ Apple Watch, Mac desktop และบริการองค์กรให้ตรงหมวดมากขึ้น
- ใช้ภาพ responsive AVIF/WebP พร้อม alt, ขนาดภาพ และโหลดภาพ Hero ก่อน
- แก้ CSS ที่ทับสัดส่วน Hero ให้แสดง 4:3 ทั้งคอมพิวเตอร์และมือถือ

## ผลตรวจสอบ

- `npm run build`: ผ่าน สร้าง 360 หน้า
- `npm run audit:images`: ผ่าน `critical=0 warning=0`
- ตรวจ HTML ทั้ง 360 หน้า: ทุกหน้ามีภาพหลักจาก repo 1 จุด ไม่เหลือ `.illus` หรือ `.hero__illustration` ตรวจทั้ง `src` และ `srcset` แล้วไฟล์ครบ พร้อม alt และขนาดภาพ
- Browser: ตรวจหน้าแรกและโน๊ตบุ๊คบนมือถือ 390px และหน้าติดต่อบนคอมพิวเตอร์ ไม่พบหน้าล้นแนวนอน ตรวจหน้าพื้นที่เพิ่มเติม
- `npm run check`: พบข้อผิดพลาดที่ไม่ได้อยู่ในไฟล์ที่แก้ครั้งนี้ 1 จุด คือ `src/pages/บทความ/[slug].astro:43` ส่ง `datePublished` ให้ `webpageSchema` ซึ่ง type ยังไม่รองรับ Build ยังผ่าน
- ตรวจในเครื่องเท่านั้น ยังไม่ได้ deploy
