## สิ่งที่ทำได้ดี

1. ตัวตรวจ SEO และลิงก์ภายในผ่าน ไม่มี title/description ซ้ำหรือขาด ไม่มีลิงก์ภายในเสียหรือหน้ากำพร้าตามเกณฑ์สคริปต์ ทุกหน้ามี canonical และ robots อย่างละ 1 ชุด
2. ภาพใน build มีไฟล์ครบ alt และขนาดภาพ ตัวตรวจ images ผ่าน
3. พบ FAQ schema 314 หน้า รวม 1,166 คำถาม ตรวจคำถามและคำตอบที่แสดงหลังตัด aria-hidden แล้วไม่พบความคลาดเคลื่อน
4. เนื้อหาหลักมีรายการใน 323 หน้า ช่วยแยกข้อมูลที่ต้องเตรียม เงื่อนไข และขั้นตอน
5. ข้อมูลธุรกิจแยกหน้าร้านอุบลราชธานีออกจากพื้นที่บริการโคราชชัดเจน; LocalBusiness ที่พบใน 359 หน้าใช้จังหวัดอุบลราชธานีสอดคล้องกัน

## จุดที่ควรแก้ตามลำดับ

### 1. เติมข้อมูล Article schema ของบทความ 37 หน้า

Article node ทั้ง 37 หน้ามี dateModified แต่ไม่มี author, publisher, image และ datePublished แม้หน้าเว็บแสดงชื่อร้านและวันที่แล้ว ควรเชื่อมข้อมูลที่มีอยู่จริงให้ครบ รวมถึง headline ที่เหมาะกับ Article

สาเหตุที่พบ: `src/pages/บทความ/[slug].astro` เรียก `webpageSchema({ type: "Article", ... })` และส่ง datePublished แต่ `webpageSchema` ไม่รองรับ/ไม่คืนค่านี้ ขณะที่มี `articleSchema` แยกไว้แล้ว นี่สัมพันธ์กับ TypeScript error ที่ตรวจพบก่อนหน้านี้

ฟิลด์เหล่านี้เป็นข้อมูลช่วยอธิบายบทความ การขาดฟิลด์ไม่ใช่หลักฐานว่า Google ลงโทษหรือไม่สามารถ index ได้ [แนวทาง Article ของ Google](https://developers.google.com/search/docs/appearance/structured-data/article)

### 2. เพิ่มหลักฐานจากงานจริงและแหล่งข้อมูลอ้างอิง

ไม่พบลิงก์อ้างอิงภายนอกใน `.main-content` ของบทความทั้ง 37 หน้า ควรอ้างอิงเอกสารผู้ผลิตตรงประเด็นสำหรับขั้นตอนเช็กแบต ลบบัญชี ตรวจสเปก และข้อจำกัดเฉพาะอุปกรณ์ ไม่ต้องเติมลิงก์เพื่อให้ครบจำนวน

คลังภาพหลักเป็นภาพเสมือนจริง และ evidence registry ยังไม่มีภาพถ่ายร้าน/สินค้า/การตรวจรับที่ยืนยันแล้ว การเปลี่ยนภาพวาดเป็นภาพเสมือนจริงช่วยการนำเสนอ แต่ยังไม่ใช่หลักฐานประสบการณ์จากงานจริง ควรเพิ่มภาพถ่ายจริงและกรณีตรวจรับที่มีรายละเอียดตรวจสอบได้เมื่อมีข้อมูล

### 3. เก็บข้อความภายในงานออกจากหัวข้อ 27 หน้า

พบหัวข้อ “หน้ารุ่นและซีรีส์ที่เกี่ยวข้องใน W2” ใน HTML 27 หน้า เช่น หน้ารับซื้อ iPhone, MacBook, ASUS ROG และกล้อง Canon ควรเปลี่ยนเป็นภาษาที่ผู้ขายสินค้าเข้าใจ เช่น “รุ่นและซีรีส์ที่เกี่ยวข้อง”

### 4. เพิ่มประโยชน์เฉพาะรุ่นและพื้นที่

พบหลายย่อหน้าเกี่ยวกับขั้นตอนและเงื่อนไขซ้ำกันใน 52 หน้า การใช้เงื่อนไขร่วมไม่ใช่ความผิดโดยตัวมันเอง แต่ควรให้เนื้อหาส่วนหลักตอบข้อแตกต่างจริงของแต่ละรุ่น/พื้นที่ มากกว่าขยายข้อความทั่วไป ตัวอย่างหน้าบางรุ่นยังใช้รายการ CPU/GPU/RAM/SSD และอุปกรณ์รวม ๆ แม้เป็นหน้าโทรศัพท์

ให้ความสำคัญกับจุดตรวจเฉพาะรุ่น ภาพตำหนิจริง ตัวอย่างผลตรวจ และเงื่อนไขนัดรับที่ร้านยืนยันได้ แทนการเพิ่มจำนวนหน้าหรือจำนวนคำอย่างเดียว

### 5. วัดผลหลังเผยแพร่

นำเวอร์ชันที่ตรวจแล้วขึ้นระบบเมื่อพร้อม จากนั้นตรวจ Search Console สำหรับ indexing/query/clicks และ Core Web Vitals และดู Bing AI Performance สำหรับข้อมูลการอ้างอิงที่บริการรองรับ การมี 359 URLs ใน sitemap ไม่ได้แปลว่า index แล้วทั้งหมด

## แยกผลตรวจผิดออกจากปัญหาเว็บ

`audit:schema` เดิมแจ้ง critical=1155 เพราะใช้ข้อความรวมของ `summary` ซึ่งมีเครื่องหมาย `+` จาก `<span aria-hidden="true">` แล้วเทียบตรงกับชื่อคำถามใน JSON-LD เมื่อใช้ข้อความที่ตัด aria-hidden ออก ทั้ง 1,166 คำถามตรงกับข้อความและคำตอบบนหน้า จึงไม่หักคะแนนว่าเว็บมี FAQ ผิด 1,155 จุด ควรแก้ตัวตรวจเพื่อไม่ให้เกิดผลบวกลวงในการตรวจครั้งต่อไป
